# Repository audit, 24 October 2026

What this repo does: This Next.js app lets editors chat with a TYPO3 instance through MCP tools. It stores conversations and encrypted credentials in SQLite and can queue content changes for approval. The audit assumes a small editor team with concurrent browser sessions, rather than a public service at large scale.

## Must fix

1. **A connection test can disclose the deployment OpenAI key.** [Issue #45](https://github.com/rupertgermann/text-to-typo3/issues/45), `src/app/api/settings/test-model-provider/route.ts`.
   - **What this is:** Settings can test whether a model provider accepts its configured credentials.
   - **Problem:** An authenticated request with `provider: "openai"` and an arbitrary `baseUrl` sends the saved or deployment OpenAI key to that URL. The actual route reproduced this with a synthetic key and intercepted request.
   - **Fix:** Bind the built-in OpenAI test to the OpenAI endpoint. Do not implicitly reuse a saved custom key at a different test endpoint.
   - **If we skip it:** An editor can extract a shared deployment credential.

2. **New messages cannot be edited or approved reliably before reload.** [Issue #46](https://github.com/rupertgermann/text-to-typo3/issues/46), `src/lib/chat-turn-resolution.ts`, `src/lib/chat-turn-persistence.ts`, and `src/lib/chat-exchange.ts`.
   - **What this is:** The browser and database identify each message when editing, regenerating, or approving it.
   - **Problem:** Both user and assistant inserts generate database IDs that differ from the browser's IDs. Sending and approving through the installed SDK returned `404 Message not found` without executing the write.
   - **Fix:** Preserve the incoming user ID. Generate, stream, and save one canonical assistant ID, and reject conflicting IDs safely.
   - **If we skip it:** Editors must reload to use message actions, and pending approvals appear broken.

3. **An approval response can execute the same write twice.** [Issue #47](https://github.com/rupertgermann/text-to-typo3/issues/47), `src/lib/chat-turn-resolution.ts`.
   - **What this is:** The server resumes a tool call after an editor approves or denies it.
   - **Problem:** Continuation replaces stored tool parts with browser data without checking that the approval is still pending. Replaying the same decision produced two identical `WriteTable` calls; the submitted tool input can also differ from the stored proposal.
   - **Fix:** Match decisions to stored pending calls and preserve their inputs. Claim the decision with a conditional database update so two tabs cannot execute it twice, and reject incomplete approval batches that could repeat earlier calls.
   - **If we skip it:** Duplicate approval requests can create duplicate TYPO3 content. Conversation ownership checks do not prevent this failure within an owned conversation.

4. **Scaffold overwrites encryption and session keys.** [Issue #51](https://github.com/rupertgermann/text-to-typo3/issues/51), `scripts/scaffold.mjs`.
   - **What this is:** The CLI writes TYPO3 connection settings into `.env.local`.
   - **Problem:** Its write step replaces the whole file, even without `--force`. Executing the CLI with an isolated filesystem and stubbed commands removed existing app secrets and provider keys.
   - **Fix:** Update scaffold-managed variables while preserving unrelated settings and comments. Use the same write behavior in every path.
   - **If we skip it:** Saved encrypted credentials become unreadable when their encryption key disappears, and existing sessions stop working.

5. **A failed regeneration deletes the previous answer.** [Issue #49](https://github.com/rupertgermann/text-to-typo3/issues/49), `src/lib/chat-exchange.ts` and `src/lib/chat-turn-resolution.ts`.
   - **What this is:** Regeneration replaces an assistant answer; editing also replaces later history.
   - **Problem:** The existing answer is deleted before provider configuration or generation succeeds. A regeneration with missing credentials returned 400 and left only the user message in SQLite.
   - **Fix:** Prepare the replacement history without deleting stored rows, then commit it with a successful replacement response. Keep the original history when preparation or generation fails.
   - **If we skip it:** An unavailable model or MCP server can destroy an answer the editor wanted to keep.

6. **Retry removes image attachments.** [Issue #50](https://github.com/rupertgermann/text-to-typo3/issues/50), `src/components/chat/ChatInterface.tsx`.
   - **What this is:** Retry submits the last user message again after a failed request.
   - **Problem:** It sends only the message text, and the SDK replaces the original message with those parts. The installed SDK reproduced attachment loss for text plus image and an empty submission for image-only messages.
   - **Fix:** Resend the original message parts with the existing message ID.
   - **If we skip it:** Retried requests lose their image context, and saved history can lose the attachment too.

7. **MCP calls keep using an expired token after refresh.** [Issue #48](https://github.com/rupertgermann/text-to-typo3/issues/48), `src/lib/mcp.ts`.
   - **What this is:** The app caches executable tools for each authenticated session.
   - **Problem:** Cached tool functions retain the token they were created with. A second lookup with a refreshed token returned the same functions, and executing one sent the old bearer token.
   - **Fix:** Reuse cached tools only when the token still matches. Invalidate the associated MCP session when credentials change.
   - **If we skip it:** Valid OAuth sessions can receive MCP authentication failures for the remaining five-minute tool-cache lifetime.

8. **A scaffold dry run creates directories.** [Issue #52](https://github.com/rupertgermann/text-to-typo3/issues/52), `scripts/scaffold.mjs`.
   - **What this is:** Dry-run mode previews the scaffold commands and file writes.
   - **Problem:** Directory creation runs before the dry-run checks. An isolated execution of the actual CLI created the instance directory during a preview.
   - **Fix:** Create the instance and state directories only during real execution.
   - **If we skip it:** Previewing a scaffold leaves unexpected directories behind.

## Verification and limits

The original baseline passed all 112 tests under the installed Node 22 runtime. The default shell used Node 24, which could not load the existing SQLite native binary; no dependency reinstall was needed.

After the fixes, all 142 tests across 32 files pass under Node 22. Lint, typecheck, and `git diff --check` also pass. Independent architect review found no remaining actionable findings after checking approval races, incomplete batches, initial-failure retry, and concurrent regeneration.

The audit traced authentication and session refresh, settings and model catalogs, chat persistence and approvals, conversation ownership and export, client retry and caching, and scaffold writes. Each reported failure has an execution case using synthetic credentials, temporary databases, the installed SDK, or stubbed external commands.

The Laziness Protocol kept the fixes in existing modules with no new dependencies. Model the Domain kept message identity and pending approval state in the existing typed message model. Tests exercise the SDK, API handlers, database, and isolated CLI rather than replacing those behaviors with mocks.

Verdict: Fix shared credential forwarding and repeated-write approvals first, then preserve message identity and stored data. No cosmetic or speculative cleanup issues were filed.

Not checked: Live TYPO3 or OAuth, real model providers, browser rendering, DDEV provisioning, process-crash recovery, or production behavior. A production build was not run to avoid replacing the existing `.next` output. The audit did not execute commands against the user's TYPO3 instance or modify the real `.env.local`.
